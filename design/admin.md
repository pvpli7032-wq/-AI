# 后台设计规格

技术栈：Vue 2.6.12 + Element UI 2.15.14，图表用已有依赖 echarts 5.4.0（读自 `ruoyi-ui/package.json`）。不引入新组件库。
通用规范见 `design/README.md`。写法沿用 `ruoyi-ui/src/views/system/commission/order/index.vue`。

**原型：** `design/admin-prototype/index.html` 是完整可点击的后台页面，2026-11-01 经用户确认，浏览器直接打开，不用安装。数据全是虚构的。`support.js` 是运行它用的库，不进生产代码。实作用 Vue 2 + Element UI，不搬原型代码；菜单、栏目、字段、跳转照原型做。

文件末尾“待确认”一节列的是新旧不一致、还没定的事，实作前先看。

## 0. 通用写法

### 0.1 页面骨架（每个列表页都一样）

1. 根节点 `div.app-container`。
2. 搜索区：`el-form :inline="true" size="small" label-width="88px"`，回车触发查询；按钮「搜索」（primary，`el-icon-search`）、「重置」（`el-icon-refresh`）。
3. 工具栏：`el-row :gutter="10" class="mb8"`，左侧操作按钮（`plain`，`size="mini"`），右侧 `right-toolbar`。
4. 表格：`el-table v-loading="loading"`，列默认 `align="center"`，长文本 `show-overflow-tooltip`，金额右侧不另设样式，前缀 `¥`。
5. 分页：`pagination v-show="total>0"`，`pageNum/pageSize`。
6. 对话框：`el-dialog append-to-body`，表单 `label-width="120px"`，底部「确定」（primary）「取消」。
7. 按钮权限：`v-hasPermi`；权限键统一为 `system:commission:*`，沿用现有写法（例：`system:commission:order:export`，`order/index.vue:51`）。新模块写成 `system:commission:<模块>:<动作>`，动作沿用若依惯例（`list`、`query`、`add`、`edit`、`remove`、`export`），模块段由实作按页面命名。
8. 路由与菜单：由迁移脚本写入（V900～V999），页面放 `ruoyi-ui/src/views/`，接口封装放 `ruoyi-ui/src/api/`。

### 0.2 状态模板

| 状态 | 表现 |
|---|---|
| 加载 | 表格 `v-loading`；对话框内数据用 `v-loading` |
| 空 | 表格默认空文案「暂无数据」；有筛选条件时空结果不额外提示 |
| 失败 | 沿用 axios 拦截器的 `$message.error`（若依默认）；表格保持上次数据不清空；对话框提交失败时对话框不关闭 |
| 无权限 | 按钮 `v-hasPermi` 不渲染；菜单无权限则不显示，直接访问路径由若依拦截 |
| 提交中 | 对话框「确定」按钮 `:loading` 防重复 |
| 成功 | `$modal.msgSuccess("xxx成功")`（若依全局封装），并刷新列表 |
| 危险操作 | 用 `$modal.confirm`，文案写清后果；关键资金操作（打款、驳回、冲正、改判）对话框 `:close-on-click-modal="false"` |

### 0.3 颜色与标签

- 平台标签沿用订单页：淘宝 `warning`、京东 `danger`、拼多多 `success`。
- 金额：正常 `#303133`；应付/风险 `#F56C6C`；正向 `#67C23A`。
- 订单展示状态（与小程序同名）：待收货 `info`、冻结中 `warning`、已结算 `success`、已退款 `danger`。后台**另外**可以显示内部状态，用于排查，放在详情的“联盟原始状态”和“状态历史”里，以接口给的文字显示，不做翻译。
- 提现状态（与小程序同名）：审核中 `warning`、打款中 `info`、已打款 `success`、打款失败和审核驳回 `danger`。
- 所有 `el-tag` 都带文字。
- 只做浅色主题，不做深色模式。

### 0.4 敏感信息

- 后台不显示联盟密钥、appKey。
- 用户手机号默认打码（接口返回打码值，需要明文时的权限和接口见缺口）。收款信息字段等打款商户选定后再定，字段确定后同样默认打码。
- 订单号（已定）：后台一律显示完整订单号，不打码，不做“点击查看”，包括订单列表、详情、无主订单认领的操作日志。理由：运营需要拿订单号去联盟后台搜索核对。小程序里的订单号则一律打码（见 miniapp.md 0.3）。

### 0.5 无障碍

见 README 第 6 节。表格操作列的文字按钮优先于图标按钮。

## 公共字典

变动类型、平台、订单状态、提现状态只在后端定义一处，经公共接口下发（暂定 `GET /admin/dict`）。所有页面的筛选、标签、导出、统计都从这里取，页面不得写死。

原型里的 `DICT` 就是字典内容，其中余额变动类型共 39 种。新增类型只改一处，其他页面自动同步。新类型如果带新的资金规则，仍要写对应业务代码。

## 返佣

### 4.1 优先级

从上往下找，先找到哪个用哪个：

1. 定向补贴：会员单独选的分组。
2. 分组补贴：会员标签返佣。
3. 新用户补贴：新人或老用户分组。
4. 默认补贴：平台默认分组。

### 4.2 返佣分组的档位

每个分组有名称、上级提成比例和若干档，条数后台自定义，可增删。

- 每档是“商品佣金小于等于多少元，分出佣金的百分之多少”。
- 档位从小到大，走第一个满足条件的档。
- 超过最高档时走最后一档。

例：设 10 元分 80%、20 元分 50%、30 元分 20%，则佣金 5 元走 80%，13 元走 50%，20.5 元走 20%，35 元走 20%。

原型里还保留金额留空的“其余”档，可以不用。

### 4.3 新人和老用户

可设统计哪种订单（已付款或已结算）、多少单以内是新人、多少单以内是老用户。
例：3 单以内走新人分组，第 4 到 50 单走老用户分组，超过 50 单走平台分组。

### 4.4 会员标签返佣

- 标签自动从标签规则同步，不手动添加。
- 竖向是树状标签，按分类可收起；横向是字典里的每个平台；每格选一个返佣分组。
- 选“不设置”就往下走优先级。
- 会员命中多个标签时，按表里从上到下，走第一个已设置的。

## 冻结

冻结分组按单笔返利金额或订单付款金额分档，决定冻结天数。
默认冻结分组按平台、新人、老用户设置。优先级：会员单独选的分组 > 新人或老用户 > 平台。会员标签只管返佣，不管冻结。

## 标签规则

- 新建标签选条件：订单笔数、近 30 天订单笔数、累计提现金额、累计返利金额、多少天内没有下单。
- 前四种可填大于、小于，可以只填一个，也可以都填，比如订单大于 3 单、小于 50 单。大于的数值必须比小于的小。标签名不能重复。
- 这四种系统每天自动打标签。
- “多少天内没有下单”只填天数，不自动更新，要后台手动点同步，列表显示最后同步时间。

## 奖励

奖励设置是一张表，每种奖励可设开关、触发条件、金额、发放时机、每人次数。首次提现奖励和累计提现奖励也在这张表里。
发出的奖励写进余额记录，并算进运营消耗。福利补贴（人工转账）也算运营消耗。

## 数据看板口径

- 用户补贴 = 用户返利 + 上级提成 + 强制补贴。
- 联盟利润 = 预估佣金 − 用户补贴。
- 运营消耗 = 所有奖励 + 福利补贴。
- 总利润 = 联盟利润 − 运营消耗。
- “有效”暂定为排除失效订单。原型里按 90% 演示，这个数字不是规则。

运营看板从上到下：订单概括（三张大卡，可切换今天、昨天、近七天、本月、上月）、经营数据、会员动态、运营消耗（每种奖励一格，取自字典）、订单详情（每平台一行加合计）、数据走势。

## 提现

- 审核方式可设：额度以下自动、以上人工，或全部人工，或全部自动。手续费为 0。
- 敞口上限和到限动作后台可控，默认转人工。敞口默认每小时算一次，提现时实时算。
- 状态名：MANUAL_REVIEW=审核中；APPROVED、SUBMITTING、PROCESSING、UNKNOWN、AWAITING_CONFIRMATION、TIMED_OUT=打款中；SUCCEEDED=已打款；FAILED=打款失败；REJECTED=审核驳回。

## 邀请和无主订单

- 无感登录。邀请码 4 位数往后排。只有新用户能绑邀请码。
- 订单没绑上时，用户提交订单号，后台核对有交易且无主则绑定；已归别人的转人工，不覆盖。

## 后台不做

申请代理模块（线 15 删除）、高佣、公众号（以后再说）、用户标签单独栏目、签到、发圈。

## A1 试算、校验和版本

**用户**：运营负责人。下面是旧规格保留的内容，页面放在返利设置，具体位置见文末待确认第 1 条。原型里没有。

### 最差毛利校验

- 对话框内按钮「校验最差毛利」：调用接口，返回结果区显示（`el-alert` + 表格）：
  - 通过：绿色 `el-alert type="success"`「最差情况下毛利为 ¥{值}，未超过上限」；
  - 不通过：红色 `type="error"`，列出最差情况的组成（用户返利、提成、补贴、成本、毛利），“确定”按钮禁用，不允许保存。
- 校验失败不是前端判断的，由接口返回；前端不自己算毛利。

### 保存与版本

- 保存后生成新版本，提示文案（固定）：「保存后只影响之后的订单，已下单的订单不受影响」。
- 编辑已启用的规则：对话框顶部显示该提示条。
- 「历史版本」：右侧抽屉 `el-drawer`，表格列：版本号、生效时间、操作人、内容摘要，可查看（只读）。

### 试算

左右布局（桌面）：

- 左：输入表单——平台、联盟佣金（元）、订单金额（可选）、用户（可选，用于命中定向/新人/阶梯，输入用户 ID）、是否新人（无用户时手选）、规则版本（默认“当前生效版本”，可选“编辑中的草稿”）。
- 右：结果——命中的比例规则、净佣金、用户返利、邀请提成、补贴、打款税务成本、平台毛利，各项带“舍入后”标识；下方“计算过程”折叠面板（按公式逐行）。
- 示例对照：页面底部不写示例数字（plan 示例数字仅供演示，不得硬编码）。
- 试算不写任何数据，按钮「试算」，请求中 loading。

### 接口（语义，见缺口 G1）

规则列表/详情/保存/停用/历史版本、最差毛利校验、试算。plan 5.5 只写“规则管理（含试算和最差毛利校验）”，没有路径与字段。

### 验收

1. 校验不通过不能保存。
2. 编辑已启用规则时有“只影响之后订单”的提示。
3. 试算页没有任何预填的数字，试算不写数据。

## A2 订单

**用户**：运营、客服。**任务**：查订单、看归因和状态历史、排查问题。

**入口**：菜单「订单管理 > 总订单」。

**与旧页面的关系（已定）**：现有 `system/commission/order/index.vue` 是旧的佣金订单页，**保留，不删不改**。新订单页是新增页面（路径由实作定，例如 `views/cps/order/`），菜单名「订单（新）」，旧页菜单保持原名。旧页含结算、退款按钮，新页不含，两页职责不同；运营如需改菜单名，可在若依菜单管理里自行调整。

### 搜索区

订单号、子订单号、平台（淘宝/京东/拼多多）、展示状态（待收货/冻结中/已结算/已退款）、绑定方式（见下）、下单时间范围（`daterange`，格式 `yyyy-MM-dd`）、用户 ID、是否可疑（是/否）。

绑定方式选项（取自 plan 4.2 的归因类型，选项文字由接口字典提供，缺口 H1）：平台确定标识、手动提交、追踪 PID、商品 ID 匹配、无主。

### 表格列

订单号（完整显示，不打码）、子订单号、平台、商品标题、付款金额、预估佣金、实际佣金、展示状态、联盟原始状态、绑定方式、归属用户、可疑标记（`el-tag type="danger"`「可疑」）、下单时间、操作（详情）。

后台可以显示佣金（运营需要）；小程序不可。

### 详情（`el-drawer` 宽 800px 或 `el-dialog`，沿用旧页用 dialog；选 dialog 宽 900px）

分区（`el-descriptions` + `el-timeline`）：

1. 基本信息：平台、订单号（完整）、子订单号、商品 ID、标题、付款金额、付款/收货/结算时间。
2. 金额：预估佣金、实际佣金、净佣金、用户返利、邀请提成、补贴、平台毛利（接口给出；没算出的显示 `-`）。
3. 归因：当前归属用户、绑定方式、置信度、决策人、决策时间；下方“归因历史”表格（只追加，不可编辑）：时间、方式、置信度、决策人、归属变化。
4. 状态历史：时间线（订单状态变化 + 返利状态变化，来自事件表），每条显示时间、前后状态、来源（联盟同步/人工/定时任务）。
5. 异常：非法跳转记录（若有，红色 `el-alert`）。
6. 原始数据：折叠面板，只读 JSON 文本（`<pre>`，最大高 300px 滚动），默认折叠。

详情只读，**本页不放“结算”“退款”按钮**（plan 的新流程里结算和退款由状态机驱动）。旧页面的结算/退款按钮保留在旧页。人工改判走 A3。

### 状态

加载 / 空 / 失败按通用。详情打开中显示 `v-loading`；订单不存在时对话框内显示“订单不存在”并提供关闭。

### 接口

订单列表、订单详情（含归因、状态历史）：线 10 第 8 项。字段名以线 10 契约为准（缺口 H2）。

### 验收

1. 能按平台、展示状态、绑定方式筛选。
2. 详情含归因历史和状态历史。
3. 可疑订单有标记。
4. 旧订单页 `views/system/commission/order/index.vue` 未改动、未删除，其菜单仍可访问。
5. 展示状态只使用四种名称（联盟原始状态单独一列，不当作展示状态）。
6. 列表和详情里的订单号是完整的，没有打码。

## A3 无主订单

**用户**：运营。**任务**：处理没有归属的订单：人工认领、改判，到期归平台。

**入口**：菜单「订单管理 > 无主订单」。

### 搜索区

订单号、平台、下单时间范围、状态（待认领/已认领/已转人工/已到期归平台）、进入无主池的原因（默认 PID 兜底、商品 ID 多人命中、PID 用完、其他；选项来自接口字典，缺口 I1）。

### 表格列

订单号（完整显示，不打码）、平台、商品标题、付款金额、进入原因、候选用户数、保留到期时间（带倒计时文字，已过期红字）、状态、操作。

操作：
- 「详情」：打开 A2 同样的详情（只读）。
- 「指定归属」：对话框——输入用户 ID（或从候选用户下拉选择），填写备注（必填），确认后订单改归属并补生成返利。二次确认文案：「确认把订单 {订单号} 归给用户 {用户}？归属后会生成返利。」订单号完整显示。
- 「转人工核对」：当两个人提交同一订单时显示，详情内列出两位提交人及各自提交时间；运营选择其一或“都不归属”，备注必填。
- 屏蔽 PID 的订单不可认领：操作按钮禁用，鼠标悬停提示“屏蔽 PID 下的订单不可认领”。
- 已入账订单的改判：按钮名「申请改判」，对话框顶部红色提示「该订单返利已入账，改判会追回原返利并留审计」；备注必填；是否需要二级审批见缺口 I3。

### 状态

通用；加上：
- 到期归平台的订单：状态标签「已归平台」，操作列只有「详情」。
- 保留天数 `{配置:无主订单保留天数}` 在页面右上角用小字显示，数值来自接口（缺口 I2）。

### 验收

1. 屏蔽 PID 订单认领按钮禁用且有说明。
2. 指定归属需要填写备注，且二次确认。
3. 已入账的改判有明确风险提示。
4. 到期订单不可认领。
5. “手动提交晚于订单到达”场景下，订单能从无主改到用户。

## A4 处罚导入

**用户**：运营、财务。**任务**：把联盟处罚单人工导入，系统据此扣返利。

**入口**：菜单「订单管理 > 处罚导入」。

### 布局

上：导入区；下：导入记录列表。

导入区：
1. 说明文字（固定）：「上传联盟下载的处罚单文件，先预览核对，再确认导入」。
2. 「下载模板」按钮（模板由接口提供，缺口 J1）。
3. `el-upload`（拖拽，`accept` 由接口规定的格式，缺口 J1；单文件；上传后不自动提交）。
4. 选好文件后显示“预览表格”：行号、订单号（完整显示，不打码）、平台、处罚类型（全部/部分）、处罚金额或比例、校验结果（通过/失败 + 原因）。有失败行时，按钮「确认导入」禁用，提示“请修正文件后重新上传”（或“仅导入通过的行”开关，默认关；缺口 J2）。
5. 「确认导入」：二次确认「将处罚 {n} 笔订单，涉及返利扣回约 ¥{x}，确认？」。数字来自预览接口。

记录列表列：导入批次号、文件名、导入人、导入时间、总行数、成功行数、失败行数、影响用户数、状态、操作（详情）。详情：该批次逐行结果（对话框，表格）。

### 状态

| 状态 | 表现 |
|---|---|
| 预览中/导入中 | 按钮 loading，禁止关闭页面前重复点击 |
| 全部成功 | `msgSuccess`，刷新记录 |
| 部分失败 | 弹出结果对话框，列出失败行与原因 |
| 文件格式错误 | 上传区下方红字，取接口文案 |
| 重复导入同一文件 | 由接口判定，文案取接口（缺口 J3） |
| 空 | 记录列表“暂无数据” |

### 验收

1. 先预览后导入，有失败行默认不能导入。
2. 导入前有影响数量的二次确认。
3. 记录列表可看每批的逐行结果。
4. 没有“撤销导入”按钮（plan 没有）。

## A5 提现审核

**用户**：财务。**任务**：审核提现单，区分“打款中”和“已打款”，处理失败和结果不明。

**入口**：菜单「提现管理 > 提现列表」。

### 提现状态名（已定）

与小程序同名，只显示五个：审核中、打款中、已打款、打款失败、审核驳回。对应关系见上文“提现”一节。列表筛选、标签、详情都只用这五个名字，不自造其他状态名；通道原始状态放详情里。

### 搜索区

提现号、用户 ID/昵称、状态（审核中/打款中/已打款/打款失败/审核驳回）、是否转人工（是/否）、转人工原因（门槛类型选项来自接口）、申请时间范围。

默认筛选：状态=审核中，且“转人工”优先排序（排序规则由接口，缺口 K2）。

### 表格列

提现号、用户（昵称 + 用户 ID）、申请金额、收款信息（字段等打款商户选定后再定；确定前该列保留位置，不展示内容；确定后打码显示）、申请时间、状态、触发审核原因（`el-tag type="warning"`，多个时多个标签，文字来自接口）、用户当前负余额标记、风控标记、操作。

操作按钮按状态显示：
- 审核中：「通过」「驳回」「详情」。
- 打款中：「详情」（无手动打款按钮，打款由通道触发；是否需要“手动触发打款”见缺口 K3）。当接口标记该单打款结果不明时，另显示「查询结果」（只查询，**不提供“重新打款”**，因为提现号就是幂等号，结果不明只能查询，plan 4.9）。
- 已打款：「详情」。
- 打款失败、审核驳回：「详情」（余额已自动退回）。

### 详情（对话框宽 800px）

- 提现单：提现号、金额、状态、通道状态、通道、通道单号、各时间点。
- 用户概况：可用、冻结、提现中、累计提现、负余额、封禁状态、历史提现次数、同收款账号当日次数。
- 触发审核的门槛：列表（门槛名、阈值、实际值），全部来自接口。注：任一门槛触发就转人工（公司决定）。
- 用户近期订单摘要（最近 N 条，N 由接口）：用于判断异常（维权笔数、结算笔数等）。
- 操作日志：谁在什么时候做了什么。

### 通过/驳回

- 「通过」：确认框「确认通过提现 ¥{金额}？通过后将进入打款」，备注可选。
- 「驳回」：对话框，驳回原因必填（下拉常用原因 + 文本框；常用原因列表来自接口，缺口 K4），确认框提示「驳回后金额退回用户钱包」。驳回原因会展示给用户，对话框里提示“用户可以看到此原因”。
- 批量审核：**不做**（资金操作逐笔处理；plan 没有批量要求）。
- 同一笔单被他人处理时：接口返回冲突，提示「该提现单已被处理，请刷新」。

### 状态

通用；加：
- 敞口超限时页面顶部 `el-alert type="warning"` 固定文案「当前垫付敞口已到上限，所有提现需人工审核」，是否显示由敞口接口返回（缺口 K5）。
- 通道不可用降级人工：顶部提示，文案取接口。

### 验收

1. “打款中”和“已打款”是两个独立状态，列表可分别筛选；状态名只有审核中、打款中、已打款、打款失败、审核驳回。
2. 结果不明的单没有“重新打款”入口，只有“查询结果”。
3. 驳回必须填原因，并提示用户可见。
4. 详情里能看到触发了哪些门槛。
5. 无批量通过。
6. 收款信息列已预留位置，字段未确定前不展示任何收款账号内容。

## A7 PID 池

**用户**：运营。**任务**：看 PID 池和单品占用率，调整租约时长，登记 PID 类型（追踪、默认、屏蔽、红包）。

**入口**：菜单「联盟管理 > PID 池」。

### 布局

上部：概览卡（`el-row` + `el-card`，4 张）：
- 追踪 PID 总数 / 占用中 / 空闲（来自接口）
- 默认 PID 数
- 当前租约时长（来自配置，显示数值 + “小时”，数值来自接口 `{配置:租约时长}`）
- 兜底进无主池次数（近 24 小时，数值来自接口）

中部：`el-tabs`：

1. 「PID 列表」
2. 「单品占用」
3. 「租约配置」

### Tab 1 PID 列表

搜索：平台、PID 类型、状态（空闲/占用中/停用）。
列：平台、PID、类型（追踪/默认/屏蔽/红包，`el-tag`）、状态、当前占用商品数、备注、更新时间、操作。
操作：「编辑类型」「停用/启用」。
规则提示（固定文案，页面顶部小字）：「默认 PID 不能放进追踪池；屏蔽 PID 下的订单不可认领；自建红包 PID 请登记成‘红包’类型」。
编辑类型：选择类型的下拉；把 PID 改成“默认”时若它当前在追踪池中，接口应拒绝，前端显示接口错误；改成“屏蔽”时二次确认「该 PID 下的订单将不能被用户认领」。

说明：用户在小程序查券（`parse` 成功）后立即转链并占用 PID，因此“最近查券次数”与占用中 PID 数直接相关。

### Tab 3 租约配置

表单：租约时长（小时，`el-input-number`，不预填默认值）、保存按钮。爆款缩短占用时间：支持“按商品覆盖”表格（商品 ID、租约时长，可增删）。提示（固定文案）：「租约只对开始之后的订单生效」。保存需二次确认。

### 状态

通用；概览卡加载失败时数字显示 `-`，不阻断下面的 Tab。

### 验收

1. 能看到每个商品的占用率并排序。
2. 默认 PID 不能被改进追踪池（接口拒绝时有明确提示）。
3. 四种 PID 类型都能识别。
4. 租约时长输入框无预填值。

### 验收
