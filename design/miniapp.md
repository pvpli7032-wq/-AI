# 小程序设计规格

通用规范、令牌、状态模板见 `design/README.md`。本文件写每个页面。

记号：
- 「固定文案」：写死在前端的界面标签（按钮名、栏目名）。
- 「接口文案」：必须从接口取的提示文案。前端只在接口整体失败时用兜底文案。
- `{字段}`：语义字段，真实字段名以线 8 契约的 DTO 为准（接口代码目前不在仓库里，见文末接口缺口）。
- `{配置:xxx}`：未定的数字或文字，由接口提供，前端不写值。

## 0. 公共规则

### 0.1 登录与返回

- 未登录判定沿用现有做法：`getToken()` 有值且 `app.globalData.userInfo` 有值（`center.js:87-98`）。
- 需要登录的新页面进入时若未登录，显示未登录态（见 README 4.4），按钮「去登录」跳 `pages/auth/login/login`。登录页如何回到来源页，现有代码没确认，见接口缺口 B3。回到页面后在 `onShow` 重新加载。
- 请求用现有 `utils/request.js` 的带 token 方法。商品浏览和转链按线 9 第 11 项改成「有 token 就带」，新页面不用 `publicGet` 发需要身份的请求。

### 0.2 转发（所有新页面）

每个新页面都实现 `onShareAppMessage`：
- `title`：固定文案「粘贴商品链接，看下单能返多少钱」。
- `path`：`/pages/index/index`，不带任何参数。商品、查券结果、订单类转发一律不带身份。
- 不设 `imageUrl`（用系统默认截图，避免截到个人金额）。钱包、订单页本身含金额，所以不设图片，并且不在页面内提供「分享」按钮。
- 邀请页例外，见 M7：只带邀请码。

### 0.3 订单号打码

小程序里的订单号一律打码（后台不打码，见 admin.md 0.4）。接口返回打码后的订单号字符串，前端直接显示，不自己切字符。不提供复制订单号的按钮。

### 0.4 提示条组件（接口文案的统一容器）

- 浅黄底 `#fffbe6`，边框 1rpx `#ffe58f`，圆角 12rpx，内边距 20rpx 24rpx，字 26rpx `#614700`（对比度约 8:1，实作后核对）。
- 左侧图标 ⚠ 仅装饰，文字必须有。
- 多条用换行列表，每条前加圆点，行距 1.6。

## M1 首页粘贴入口

**页面**：`pages/index/index`（现有）。新增一个粘贴区块，并改两处现有文案（见文末「首页现有文案改动」），其他区块（安全提示横幅、代理入口、搜索、平台选择、热门商品）保持不动。

**用户任务**：看到一个商品，复制了链接或口令，想知道下单能返多少钱。

**入口**：tab「首页」，进来就看到。

### 布局（手机，宽 750rpx）

位置：放在「安全提示横幅」和「代理入口」之后、「搜索栏」之前。已定：不挤掉原有的代理入口，粘贴区放在代理入口之后。

```
┌ 卡片（白底，margin 0 24rpx，圆角 16rpx，内边距 24rpx）──────┐
│ 粘贴商品链接，查下单能返多少钱            (标题 32rpx 加粗) │
│ 支持淘宝、京东、拼多多                    (说明 24rpx #666)│
│ ┌ 输入框 textarea ───────────────────────────┐ │
│ │ 把商品链接或淘口令粘贴到这里               │ × │ │
│ └────────────────────────────────────────┘ │
│ [ 粘贴 ] (次按钮, 宽 200rpx)   [ 查返利 ] (主按钮, flex:1) │
└──────────────────────────────────────────────┘
```

- 输入框：`textarea`，`auto-height`，最小高 120rpx，最大高 240rpx 超出滚动；最大长度见接口缺口 B5，未定前不设自定义限制；底色 `#f7f8fa`，圆角 12rpx，内边距 20rpx，字 28rpx。
- 清空按钮「×」：输入框有内容时在右上角显示，点击区 88rpx × 88rpx，带 `aria-label="清空"`。
- 「粘贴」按钮：高 88rpx。
- 「查返利」按钮：高 88rpx，输入框去掉空白后为空时禁用。

### 行为

| 操作 | 行为 |
|---|---|
| 长按输入框粘贴 | 系统自带，不做任何处理 |
| 点「粘贴」 | 在点击处理函数里调用 `wx.getClipboardData`；有内容则填入输入框（覆盖原内容）；无内容 toast「剪贴板里没有内容」；调用失败 toast「粘贴失败，请长按输入框手动粘贴」 |
| 点「×」 | 清空输入框，焦点回到输入框 |
| 点「查返利」 | 去掉首尾空白；已登录则 `wx.navigateTo` 到 M2，用 `eventChannel` 把输入文本传过去（不放进 URL 参数）；未登录则 toast「请先登录」后跳登录页，输入框内容保留（页面栈保留，不清空） |
| 页面 `onLoad`、`onShow`、`onShareAppMessage` | 绝不读取剪贴板 |

禁止：自动读取剪贴板、弹出「检测到链接」提示。

### 状态

| 状态 | 表现 |
|---|---|
| 默认 | 输入框空，「查返利」禁用 |
| 有内容 | 「查返利」可用 |
| 未登录 | 区块照常显示，点「查返利」才提示登录（现有首页允许未登录浏览商品） |
| 加载/失败/空 | 本区块没有自己的加载；查询发生在 M2。商品列表区的加载、空保持现状 |
| 点击防抖 | 800ms 内重复点击「查返利」只响应一次 |

### 文案（固定）

标题「粘贴商品链接，查下单能返多少钱」；说明「支持淘宝、京东、拼多多」；占位符「把商品链接或淘口令粘贴到这里」；按钮「粘贴」「查返利」。

### 接口

无直接调用。M2 调用 `POST /miniapp/convert/parse`。

### 无障碍

- 输入框有可见标题作为标签。
- 两个按钮和清空键的触控区均 >= 88rpx。

### 首页现有文案改动（归线 13 实作）

首页热门商品卡上写着「预估佣金 ¥xx」（`index.wxml:107-110`，标签文字在 `index.wxml:108`），商品弹窗提示里有一句「分享给好友即可获得佣金奖励」（`index.wxml:152`）。与「只显示预计返利」不一致，已定处理如下：

1. 商品卡标签「预估佣金」改为「预计返利」，数值字段不变。
2. 弹窗提示 `tpwd-tip` 删掉「分享给好友即可获得佣金奖励」这一句，保留平台打开提示那一句。理由：该句含「佣金」，且分享奖励机制由 M7 承担。
3. 首页其他逻辑不动。商品详情页（`pages/goods/detail`）的佣金文案由线 9 第 9 项负责，不在本线范围。

## M2 查券结果

**页面**：`pages/convert/result/result`（新）。

**用户任务**：确认这个商品能返多少钱，然后去下单；或者知道为什么不能返。

**入口**：M1 点「查返利」。页面进入时通过 `eventChannel` 取输入文本；取不到（冷启动、刷新）时 toast「请回到首页重新粘贴」并 `navigateBack`，无上一页则 `switchTab` 到首页。

### 流程

已定：查券时就分配 PID，查券时就转链。

1. 进入 -> 加载态 -> 调 `POST /miniapp/convert/parse`（入参：输入文本）。
2. 成功且有预计返利 -> 正常态，并立即调 `POST /miniapp/convert/link` 转链（此时分配 PID，拿到口令或链接后存在页面内）。转链期间底部主按钮显示「正在准备…」并禁用。
3. 转链成功 -> 底部主按钮可用。转链失败 -> toast 接口错误信息，按钮改为「重新获取」，点击重新调 `convert/link`。
4. 点底部主按钮（复制口令或链接）只写剪贴板，不再发请求。
5. 无佣金、佣金过低、解析失败、限流、网络失败这些非正常态，不调 `convert/link`。

### 布局（正常态）

```
[商品图 200rpx 方形] 标题（最多 2 行，省略）
                     [淘宝] 券 ¥{券额}
                     券后价 ¥{券后价}  划线价 ¥{原价}(删除线)
────────────────────────────────────
 预计返利                    ¥ 9.00   (48rpx 加粗, #ff6600)
 {接口文案:返利说明}         (24rpx #666)
────────────────────────────────────
 [提示条：下单前请看]  {接口文案:绑定提示列表}
────────────────────────────────────
底部固定栏： [ 复制口令去下单 ]（淘宝） /  [ 复制链接去下单 ]（京东、拼多多）
             次要文字链接：下单后没收到提醒？提交订单号
```

- 商品图 200rpx × 200rpx，圆角 12rpx，`mode="aspectFill"`。
- 价格：券后价 40rpx 加粗 `#333`；划线价 24rpx `#666` 删除线；券用 `tag-danger`。
- 「预计返利」行：整行是独立白卡，上下内边距 32rpx，标签 28rpx `#333`，金额 48rpx。金额旁不显示比例、不显示「佣金」二字。
- 底部栏：高 120rpx + 安全区，白底，顶部阴影，主按钮满宽（左右各留 24rpx）。页面内容底部留出同高度。

### 绑定提示（plan 4.2，全部接口文案）

接口返回一个提示列表，前端依次显示，不增删、不改写。plan 要求涵盖的内容（用于验收对照，文字由接口给）：
1. 不要使用购物红包；
2. 购物车和收藏里的旧商品要先删；
3. 绑定后取消订单或维权，返利会失效；
4. 下单后 `{配置:N}` 分钟内没收到绑定提醒，就来提交订单号。

显示位置：
- 页面中部提示条（始终显示，不折叠）。
- 复制成功后再弹一次底部抽屉（见下），内容同一份接口文案，带「我知道了」「去提交订单号」。

### 按钮行为

| 按钮 | 行为 |
|---|---|
| 复制口令/链接去下单 | 转链已完成时可点。点击 -> `wx.setClipboardData` 写入页面内已有的口令/链接 -> 弹出绑定提示抽屉，标题固定文案「已复制，打开{平台名}下单」。写入失败：toast「复制失败，请再点一次」，按钮保持可点 |
| 正在准备…（禁用） | 转链请求中，不可点 |
| 重新获取 | 转链失败后出现，点击重新调 `convert/link` |
| 抽屉「我知道了」 | 关闭抽屉，留在本页 |
| 抽屉「去提交订单号」 | 跳 M4 |
| 底部链接「提交订单号」 | 跳 M4 |

写入剪贴板是用户点击触发的写入，不是读取，允许。

### 状态

| 状态 | 条件 | 表现 |
|---|---|---|
| 加载 | 请求中 | 商品卡骨架 + 居中「正在查询返利…」；不显示底部栏 |
| 正常 | 有商品、有预计返利 | 上述布局 |
| 无佣金 | 接口判定无佣金 | 商品卡照显（若接口给了商品信息）；去掉「预计返利」卡，换成无返利卡：图标 + 标题固定文案「这个商品暂时没有返利」+ 接口文案（原因）；若接口有同款推荐则下方列表「同款推荐」（缩略图、标题、券后价、预计返利，点击进商品详情）；底部栏改为次按钮「重新粘贴」（`navigateBack`）；不显示「复制口令」，不调 `convert/link` |
| 佣金过低 | 接口判定佣金过低 | 同「无佣金」布局，原因文案取接口，标题固定文案「这个商品返利太少，暂不支持」 |
| 比价订单提示（拼多多） | 接口返回比价提示 | 在正常态商品卡下方加一条提示条，文字全取接口；没返回就不显示。是否显示由后台设置决定，前端不判断平台 |
| 解析失败 | 接口判定解析失败 | 图标 + 标题「没认出这个链接」+ 接口文案（原因）+ 固定说明「请复制商品页的分享链接或淘口令」；按钮「重新粘贴」「回首页」 |
| 限流/忙 | 接口返回限流 | 同失败态，文案取接口，按钮「稍后再试」（等同重新请求，点击后 3 秒内禁用） |
| 网络失败 | 请求出错 | 失败整页模板，「重新加载」重新请求 parse |
| 未登录 | 无 token | 未登录整页模板（正常情况下 M1 已拦住，直接打开本页时用） |
| 缓存命中 | 同商品短时间重复查 | 与正常态一样，用户无感知，不加提示 |

三种失败（解析失败、无佣金、佣金过低）必须是三种不同的画面和不同的文案来源，因为后台漏斗要分别统计。

### 接口

| 数据 | 接口/字段（语义） |
|---|---|
| 商品图、标题、平台、券、券后价、划线价 | `POST /miniapp/convert/parse` 返回 `{商品}` |
| 预计返利 | `{预计返利}`（金额，接口算好） |
| 结果类型 | `{结果类型}`：成功、解析失败、无佣金、佣金过低、限流（真实枚举以接口为准） |
| 说明和提示 | `{返利说明}`、`{绑定提示列表}`、`{比价提示}`、`{失败原因}` |
| 同款推荐 | `{同款推荐列表}`（接口缺口 B4） |
| 口令/链接 | `POST /miniapp/convert/link`，在 `parse` 成功且有预计返利后立即调用，返回 `{口令或链接}`、`{平台}` |

### 无障碍

- 预计返利金额的读屏文本：「预计返利 9.00 元」。
- 提示条文字对比度 >= 4.5:1。
- 抽屉打开时焦点落在抽屉标题，关闭回到触发按钮。
- 底部主按钮禁用时文案为「正在准备…」，不只靠置灰表达状态。

## M3 我的订单

**页面**：`pages/order/list/list`（新）。

**用户任务**：看自己的订单现在是什么状态，返利多少、什么时候能提现。

**入口**：用户中心「我的订单」及四个状态快捷入口；钱包页「查看我的订单」。

### 布局

```
顶部 Tab（固定，白底，高 88rpx）： 全部 | 待收货 | 冻结中 | 已结算 | 已退款
列表（卡片）：
┌──────────────────────────────────┐
│ [淘宝]  订单号 12****89            [待收货]   │
│ [图 140rpx] 商品标题（2 行）                 │
│              下单时间 2026-10-30 12:00        │
│ ────────────────────────────  │
│ 预计返利 ¥9.00      {接口文案:状态说明}      │
└──────────────────────────────────┘
列表底部：找不到订单？提交订单号 >
```

- Tab：横向可滚动 `scroll-view`，选中项文字 `#667eea` 加粗，下划线 4rpx；每项最小宽 150rpx，高 88rpx。顺序固定：全部、待收货、冻结中、已结算、已退款。
- 卡片：沿用 `.card`；平台用 `tag`（淘宝 warning、京东 danger、拼多多 success，与后台订单页的颜色对应）。
- 状态标签：右上角，样式见 README 4.2。
- 金额行：
  - 待收货、冻结中：标签「预计返利」，金额 `#d4380d` 32rpx 加粗。
  - 已结算：标签「已到账返利」，同样式（取 `{返利金额}`）。
  - 已退款：标签「返利」，金额灰色 `#666` 加删除线，旁边接口文案说明。
  - 订单无返利（例如拼多多比价订单）：不显示金额，显示「这单没有返利」+ 接口文案原因（原因来自接口，不要自己判断）。
- 状态说明 `{状态说明}`：右对齐 24rpx `#666`，例如到期日、退款原因，全部接口文案，前端不拼日期。
- 点击卡片：打开底部抽屉「订单详情」（不新开页面）。
  - 内容：商品图、标题、平台、订单号（打码）、下单时间、状态标签、金额行（同上规则）、状态说明、状态历史时间线（`{状态历史}`：时间 + 展示状态名 + 接口说明，只显示四种名称，若历史条目的名称不在四种内，按 README 4.2 灰色显示接口给的文字）。
  - 不显示：佣金、比例、服务费、PID、归因方式、内部状态码。
  - 底部按钮「关闭」。抽屉高度最大 80vh，内部可滚动。

### 状态

| 状态 | 表现 |
|---|---|
| 加载（首次/切 Tab） | 列表区居中 `.loading`；切 Tab 清空列表后加载 |
| 空（全部） | 图标 + 「还没有订单」+ 说明「粘贴商品链接查返利，下单后订单会出现在这里」+ 主按钮「去查返利」（`wx.switchTab` 到首页） |
| 空（某个状态） | 图标 + 「这里没有订单」，不带按钮 |
| 失败 | 整页失败模板；翻页失败见 README |
| 未登录 | 整页未登录模板 |
| 无返利订单 | 见上，仍在列表中显示，不隐藏 |
| 下拉刷新 | 重置页码、重新加载当前 Tab |
| 触底 | 加载下一页；到底显示「没有更多了」 |

### 按钮行为

| 操作 | 行为 |
|---|---|
| 切 Tab | 带状态参数请求 |
| 点卡片 | 开抽屉 |
| 点「提交订单号」 | 跳 M4 |

### 接口

`GET /miniapp/orders`（`MiniappUserController.java:49` 已有同路径旧接口；线 10 第 8 项说明新的展示状态用四种名称）。

| 数据 | 语义字段 |
|---|---|
| 状态筛选 | 请求参数 `{展示状态}`（四种之一或不传），真实参数名/取值以接口为准（缺口 A1） |

### 无障碍

- Tab 的选中项设 `aria-selected` 语义；每个 Tab 触控 >= 88rpx。
- 状态标签带文字；金额带「元」读屏文本。

## M4 提交订单号

**页面**：`pages/order/claim/claim`（新）。

**用户任务**：下单后没收到绑定提醒，把订单号交给系统认领。

**入口**：M2 底部链接/抽屉；M3 底部链接；用户中心「提交订单号」。

### 布局

```
[提示条] {接口文案:提交说明}      （例如“在哪里找订单号”“时限”，全由接口提供）
订单号 *（标签 28rpx）
┌────────────────────────────┐
│ 请输入订单号                │
└────────────────────────────┘
（输入框下方错误区，红字 24rpx #cf1322）
[ 提交 ]  主按钮满宽
```

- 输入框：`input`，`type="text"`（订单号可能含字母），高 96rpx，右侧清空键。不自动读剪贴板；用户可长按粘贴。
- 去掉首尾空格后提交。
- 平台选择：由接口决定是否需要，见缺口 C1。设计默认**不放**；如接口要求，在订单号上方加三选一分段选择「淘宝｜京东｜拼多多」，默认不选，必选。
- 提交按钮：订单号为空时禁用；请求中变「提交中…」并禁用。

### 结果

| 结果 | 表现 |
|---|---|
| 成功 | 输入区替换为成功卡：绿色 ✓ 图标 +「提交成功」+ 订单摘要（打码订单号、商品标题、预计返利）+ 接口文案。按钮「查看我的订单」（跳 M3）、「再提交一个」（回到表单并清空） |
| 失败（具体原因） | 输入框下方红字显示接口给的原因文案，保留输入内容。plan 4.2 要求的六类原因（未找到、别人已绑定、自己已绑定、屏蔽 PID、失效状态、超出时间）各有自己的接口文案；前端不合并、不改写。仅在接口没给文案时用兜底「没能提交成功，请检查订单号后再试」 |
| 转人工 | 两人提交同一订单时接口返回“待核对”类结果：显示蓝色信息卡「已收到，正在核对」+ 接口文案，不当作错误，不显示红色 |

| 限流 | 取接口文案 |
| 未登录 | 整页未登录模板 |

- 输入框有可见标签「订单号」。

## M6 提现

**页面**：`pages/wallet/withdraw/withdraw`（新），顶部两个分段：「申请提现」「提现记录」。

**用户任务**：把可提现的钱提出来；看提现到哪一步了。

**入口**：M5「提现」「提现中」「累计提现」。

### 分段 1：申请提现

```
可提现 ¥128.50
提现金额
┌──────────────────────┬────────┐
│ ¥  请输入金额                   │ 全部提现 │
└──────────────────────┴────────┘

```

- 金额输入：`input type="digit"`，高 96rpx，28rpx；`¥` 前缀；仅允许数字和最多两位小数；不在前端限制最小/最大/整数（这些数字未定，由接口返回错误文案）；接口提供了 `{最小值}`、`{最大值}`、`{整数提现}` 时才做预检。
- 「全部提现」：把接口给的 `{可提现上限}` 填入（缺口 E2），前端不自己取整。
- 规则列表：提示条样式，位置在金额下方。
- 收款信息区（已定）：收款信息字段等打款商户选定后再定。本版规格不定任何字段，不编造「微信/支付宝/银行卡/姓名/账号」等输入项或展示项。页面在规则列表与「申请提现」按钮之间预留一个独立区块位置（卡片容器，上下间距 20rpx），本版该区块不渲染任何内容、不占高度；字段确定后由新规格补充，届时不需要改整体布局。
- 按钮：金额为空、`<= 0`、或提现不可用时禁用。
- 点击「申请提现」-> 确认弹窗：标题固定文案「确认提现」，内容「提现 ¥{金额}」+ 接口文案提示（审核时效等），按钮「取消」「确认提现」。收款信息字段确定后，在内容里补一行收款信息。确认后调 `POST /miniapp/withdrawals`，按钮 loading。
- 提交结果：
  - 成功：显示成功卡「已提交」+ 接口文案（例：审核时效），按钮「查看提现记录」（切到分段 2 并刷新）、「返回钱包」。

  - 网络超时/结果不明：不允许直接再点提交。显示「网络不太好，请先到‘提现记录’确认是否已提交，再决定要不要重试」，并自动切到记录分段并刷新。原因：避免重复申请。是否有幂等号见缺口 E3。
  - 提现受限（负余额、封禁、受限）：进入页面时就显示提示条 + 禁用按钮，文案取接口。
- 用户看不到“哪一条门槛触发了转人工”：提交成功后统一展示 `审核中`。前端不显示风控原因。

1. 首页出现粘贴区块，位置在安全提示横幅和代理入口之后，搜索栏之前。
2. 全局搜索 `getClipboardData`：只出现在 M1「粘贴」按钮的点击处理函数里。
3. 输入框为空时「查返利」禁用；有内容可点。
4. 未登录点「查返利」提示登录，输入内容保留。
5. 原有首页功能（搜索、平台选择、商品列表、淘口令弹窗）行为不变。
6. 首页商品卡标签是「预计返利」，`index.wxml` 里不再有「预估佣金」；淘口令弹窗提示里不再有「佣金奖励」。

**M2**
1. 正常态显示“预计返利”，没有“佣金”“佣金率”字样。
2. 无佣金、佣金过低、解析失败三种画面各不相同，文案取接口。
3. 绑定提示在页面中部和复制成功后的抽屉里都出现，内容完全来自接口。
4. `parse` 成功且有预计返利时，自动调用一次 `convert/link`；无佣金、佣金过低、解析失败、限流时不调用 `convert/link`；点击「复制口令/链接去下单」不再发请求（抓包或日志核对）。
5. 转链期间按钮显示「正在准备…」且不可点；转链失败显示「重新获取」。
6. 比价提示只在接口返回时出现。
7. `onShareAppMessage` path 不带参数。
8. 冷启动直接打开本页时回到首页并提示。

**M3**
1. 五个 Tab，名称是“全部/待收货/冻结中/已结算/已退款”。
2. 页面上看不到内部状态码。
3. 订单号是打码的，来自接口。
4. 详情抽屉只有预计返利，无佣金字段。
5. 各 Tab 空状态、全部空状态、失败、未登录都能复现。
6. 无返利订单仍在列表显示，并说明原因。

**M4**
1. 六类失败原因都显示各自的接口文案，没有被合并成同一句。
2. 待核对结果显示为蓝色信息卡，不是红色错误。
3. 成功后能跳订单页或继续提交。
4. 不自动读剪贴板。

**M5**
1. 显示可提现、冻结中、提现中、累计提现四个数。
2. 负余额时“可提现”变“待抵扣”，提现按钮禁用，提示条取接口文案。
3. 空明细文案不含具体天数。
4. 无活动时活动区不显示。

**M6**
1. 规则文案（最低、最高、次数、日期、整数）全部来自接口，前端无这些数字。
2. 申请前有确认弹窗；结果不明时不能直接重复提交。
3. 记录列表区分“已审核”和“已打款”；状态名只有「审核中」「已审核」「已打款」「已退回」；已退回显示退回原因。
4. 用户看不到风控触发原因。
5. 页面里没有收款方式、收款人、账号等任何输入项或展示项；申请按钮上方预留了收款信息区块位置，且当前不渲染。

**M7**
1. 所有登录用户可进入，邀请码来自接口。
2. 分享 path 只带 `invitationCode`，不带其他身份信息。
3. 邀请码缺失时分享按钮禁用。
4. 页面没有手动绑定入口、没有邀请明细、没有多级。
5. `center.js` 里不再引用 `/images/share-bg.png`；没有新增图片文件。

**M8**
1. 新增 4 个菜单项，「分享推广」「关于我们」仍在。
2. 概览条和订单状态入口只在已登录时显示。
3. 未登录点新入口被拦住。
4. 「提现管理」指向 M6 路径；「我的团队」保留，点击仍提示“页面开发中”；其余 `menuList` 的 `url` 都在 `app.json` 的 `pages` 里。
